# Slice 2, first half: the shelf becomes visible

Session record, 2026-06-12, on the `leek-list` branch. The first read verb, and deliberately the smaller half of slice
2: `list` and `info` land on separate branches, each with its own just-in-time plan.

## The design

`leek list` got its decision record before its code ([ADR 0011](../decisions/0011-list-is-albums-in-shelf-order.md)):
albums only — the album is the primary entity, so the default view of the library is the view of its albums — in **shelf
order** (artist, year with missing years last, title: exactly the library tree's order, ADR 0010), narrowed by **bare
terms** that AND together and match case-insensitively in artist, title, or year. Both terms entered the glossary.

The query-language question was the fork to steer past: beets' query language grew by accretion into the stringly-typed
field machinery, so field-qualified terms, comparisons, and negation are an explicit open question with a punt — bare
substring terms until a real query demands more. Two smaller decisions worth recording: terms match *data*, never
display fallbacks (an artistless album is not found by searching `unknown`), and an empty result is an answer, not an
error — exit 0, with the note on stderr so stdout stays a clean list. The empty-library note points at `leek add`,
keeping refusals-as-navigation alive in a verb that never refuses.

## What was built

`library.list_albums` reads the merged view in one statement — the first code to *use* the merged view, which is what
the slice was for: `list` never touches the source layer, and the separation now earns its keep. The CLI renders a
borderless four-column table, Unknown Artist in dim italic — visibly a fallback, not data. Tests arrived first, per the
plan: sixteen across the query layer and the CLI surface, plus a `shelve` conftest fixture that plants merged-view rows
directly for shapes the corpus cannot materialise (artistless albums, year mixes within one artist).

Dogfooded against a materialised scratch library through the installed `leek`: shelf order held, terms narrowed, the
notes stayed off stdout, and the piped output stayed greppable.

## The review

A review round (2026-06-13) caught the branch breaking its own contract. ADR 0011 promises one album per stdout line,
but the themed table wraps long rows at width 80 when stdout is not a terminal — one long-titled album became four
physical lines in a pipe, so `leek list | wc -l` lied and `| grep` missed. The dogfooding above missed it because the
corpus's names are short; the session's "piped output stayed greppable" was true only of the albums it tried. The fix
follows `version`'s precedent — branch on `console.is_terminal`: the table for eyes, one tab-separated record per album
for pipes — with a deliberately long-titled regression test, and the ADR now says "one per line" is literal.

The same round folded the branch onto main's decisions rename: the record moved to `docs/decisions/0011` and gained its
`Status: Decided` line (a plain rebase would have silently resurrected the dead `docs/adr/` directory), cross-links
followed, and the INNER join in `list_albums` gained a comment naming the invariant it leans on — every album has a
track, true until some future verb deletes tracks.

## Open ends

`leek info` is the slice's second half and gets its own plan. The corpus still has no artistless album — the `shelve`
fixture covers the gap for now, but a properly untagged corpus album would let the add pipeline produce the Unknown
Artist case end to end.
